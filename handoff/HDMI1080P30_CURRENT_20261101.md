# 当前项目计划：1080p30 电脑 HDMI 输入（2026-11-01）

## 目标与路线

本页依据本用户最新明确要求纠正仓库全局入口：**电脑 HDMI 输入 → FPGA 畸变矫正 → HDMI 输出；有效图像 1920×1080 progressive，目标 30 fps / 显示刷新 30 Hz。** 这是目标，不是已实测达到的结果；30 Hz 扫描、仿真处理吞吐与每秒实际新增图像必须分别报告。摄像头/新镜头采集不是本主线的前置任务。

已有外部 RX 并行像素 → 输入观察器 → 采集 CDC/DMA → DDR → 矫正引擎 → 扫描/B4 的 RTL 路径；**物理 HDMI 完整链路尚未实测通过**。当前主线仍为固定 Penn 参数、0°；没有动态 K/D 或角度加载，不沿用历史摄像头的动态角度能力声明。

## 接续与交接契约

1. **唯一 RTL 集成负责人**推进 HDMI 主工程；摄像头分工与文档在独立分支，不直接覆盖共享 DDR IP、约束或已验收候选。跨分支借鉴须先核对模块接口、时钟/复位、参数、精确端点与来源差异；不复制别的 ADF 的例外或时序数值。
2. 下一项主线工作是让当前保留 UART 候选闭合 setup、DDR recovery/removal 与 IO/CDC 证据，再用同一源码/约束/ADF 绑定的候选验收；不得删 UART、放宽错误判定或用局部通过绕开门禁。新候选若替换基线，须同步准确版本和未过项。
3. 每次交接至少写：路线与目标分辨率/刷新/新增帧率、分支与 commit、top/参数、ADF/位流 SHA、测试尺寸与环境、通过/失败/未执行、硬件状态来源、下一位第一项任务。来源不明的“当前已通过”不可接续。
4. 放行后才安排物理 HDMI 输入/输出、实际像素与新增帧率、持续运行验证；上电、下载和 Flash 操作仍需相应现场确认与授权。任何仿真或 CI 都不替代这些验收。
5. 同步时同时更新 [README](../README.md) 与 [CURRENT](CURRENT.md) 的醒目入口；历史技术记录保持原证据，不再让某个分工的“下一步”覆盖全仓目标。
