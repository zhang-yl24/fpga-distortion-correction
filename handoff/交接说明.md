# FPGA项目交接说明

## 先确认当前路线（2026-11-01 更正）

**项目主线目标：电脑 HDMI 输入 → FPGA 畸变矫正 → HDMI 输出，1920×1080 progressive、30 fps / 30 Hz。** 目标不等于已实测达到；摄像头及新镜头采集不是当前主线的前置条件。先读 [当前计划与分工交接契约](HDMI1080P30_CURRENT_20261101.md) 和 [CURRENT 顶部](CURRENT.md)，再选择对应分支、候选和工具。

同学的 VGA 标定成果及 720p 摄像头候选保留为独立分工：VGA 已通过 PR #16 合入 main，720p 在 PR #17 仍是离线阶段。它们不能代替当前 HDMI 主工程的时序/IO/CDC、物理输入、实际新增帧率及长稳验收。当前主工程没有硬件放行；历史命令不是立即操作许可，供电、位流和现场状态须重新确认。

## 先了解已完成的工作

历史已验证基线的完整链路为OV5640摄像头→DDR→畸变坐标映射→双线性插值→Gamma→HDMI，输入640×480，核心125MHz。已实现按键、串口角度控制及自动旋转，真实相机标定和同源逐像素核对流程已建立。D5管脚已由AA22修正到AA23。它是历史实板基线，不表示当前SRAM运行该版本；当前处理/输出候选和阶段任务以最新交接为准。

## 获取完整版本

推荐克隆私有仓库；使用网页“Code→Download ZIP”也能取得仓库文件。队友需先拥有仓库访问权限。

```powershell
git clone https://github.com/zhang-yl24/fpga-distortion-correction.git
cd fpga-distortion-correction
```

首次交接使用[handoff-20261010版本附件](https://github.com/zhang-yl24/fpga-distortion-correction/releases/tag/handoff-20261010)：

| 附件 | 内容 | 什么时候需要 |
| --- | --- | --- |
| starter-artifacts.zip | heartbeat、corrected_gamma_d5、两种修正D5的采集版的必要位流和报告，及采集回归门禁所需记录 | 第一次实板下载、采集、使用现成稳定版本 |
| build-history.zip | 本次交接时完整的历史构建目录 | 继续查历史仿真、失败路由、编译或下载日志 |
| evidence-history.zip | 完整的results/verified封存目录，保持原证据字节不变 | 查证封存结果、源码快照和复核历史 |

附件是仓库的补充，网页源码ZIP不会自动包含附件。仓库中的`handoff/manifests/release-assets.json`列出附件大小、文件数和SHA256。附件内部路径均以仓库根目录为基准。

将附件下载到仓库外或`_handoff`目录，再从仓库根目录导入；无需重新编译：

```powershell
python handoff/import-artifacts.py C:/Downloads/starter-artifacts.zip
```

导入前会核对附件SHA256；已有文件内容不一致时拒绝覆盖。完整历史可以分别用相同命令导入另外两份附件。`--replace`会允许覆盖不同的本地文件，仅在已经保存自己的改动时使用。

## 配置各自的工具

建议将工程放在不含空格和中文的短路径，例如`D:/FPGA/team`。源码包含中文文档；构建工具对工作目录的兼容性另行确认。

需要：Windows、Git、Python 3.12或兼容版本、完整PDS 2022.2-SP6.4（PG2L100H/FBG676支持）、JTAG驱动、CP2102驱动。RTL仿真入口使用Vivado 2017.4的xvlog/xelab/xsim；云端Python参考检查不需要Vivado或PDS。

参考环境固定NumPy 2.2.5和OpenCV 4.11.0.86，与原开发电脑的已安装版本一致；安装时使用仓库依赖文件，避免直接安装最新版改变标定接口。

PDS安装软件、本机许可证和驱动配置不随仓库提供。根据自己电脑安装位置配置路径，不要复制他人的许可证。必要DDR/PLL IP文件已经包含在`distortion/platform`，请保留原有厂商归属和许可。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-team.txt
Copy-Item team-config.example.json team-config.local.json
```

编辑`team-config.local.json`中的Python、PDS和Vivado路径。此文件只保留在各自电脑，不提交。也可用`FPGA_PYTHON`、`FPGA_PDS_BIN`和`FPGA_VIVADO_BIN`环境变量覆盖配置。串口命令须显式传入本机端口；示例COM5不是自动识别结果。

第一次准备现场操作时，创建本机状态文件：

```powershell
Copy-Item handoff/status-template.json distortion/status.json
```

模板表示“本机尚未确认”，不把前一位队员的连接状态当作当前状态。已有本机状态文件时不要覆盖。

## 使用现成稳定版本

先导入`starter-artifacts.zip`、配置本机PDS和Python，再连接板卡与显示器。先下载待机版确认设备，然后下载稳定演示版；这两条命令会真实访问开发板：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File distortion/tools/program-heartbeat.ps1 -Target heartbeat -Frequency 5MHz
powershell -NoProfile -ExecutionPolicy Bypass -File distortion/tools/program-heartbeat.ps1 -Target corrected_gamma_d5 -Frequency 5MHz
```

位流、源文件、最终时序和管脚都要匹配才允许下载。稳定演示位流SHA256为`069D8ACEF8DED0CD62D19EE47C83E06910DF35BD0D76A9DF29403A8A14B877CF`。下载器会拒绝使用摄像头D5=AA22的旧版本。

从仓库根目录发送一次角度指令并有限观察，结束后工具会实际下载heartbeat待机：

```powershell
.venv/Scripts/python.exe distortion/tools/host-angle.py --angle 13.7 --port COM5 --execute --observe-seconds 20 --output distortion/results/team-angle-check.json
```

导入包提供host_control_sim目录所需记录；若自行删除build目录，先重新导入starter附件或创建工具需要的输出目录。相机采集和光学分析继续沿用实验操作表，只使用D5修正后的光学数据。

每轮重载测试结束都要实际回heartbeat。仅关闭电脑软件不能停止FPGA逻辑；重载之间至少待机60秒。按已有实验策略做有限测试，持续运行须现场观察和记录温度。当前只下载易失SRAM，断电后需重新下载；Flash自主启动没有验收。

## 接着修改和构建

所有设计源文件保留原样，包括含旧工作目录的历史Tcl。构建入口在生成的`build/<target>/portable-build.tcl`中重定位路径，不改写已封存的原始设计文件。

需要重新构建时由接手队员在自己的工具环境执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File distortion/tools/build-pds.ps1 -Target corrected_gamma_d5
```

入口会保留已有构建目录，再从空工作目录构建、检查最终时序并绑定源码SHA。新候选的源文件变化会让旧位流验证失败，这是预期行为；不要修改哈希来绕过门禁。修改D5隔离候选的其他设计内容时，应建立独立候选并更新相应验证，不能继续把它标作“只改D5”。

已有构建在跨电脑恢复时使用文件哈希验证；新构建仍保留源文件、数据库和报告的时间检查。保存了原始入口副本于`handoff/original-entrypoints`，供历史对照，不从该目录直接运行。

## 轮流推进与提交

1. 接手前读取CURRENT.md，确认上一轮已提交，再拉取最新代码。尚有自己的未提交修改时先保存，避免覆盖。
2. 主工程由唯一 RTL 集成负责人推进；摄像头 VGA/720p、独立候选和文档在各自分支推进。跨分支借鉴先提交精确差异、来源和适用条件，由主工程负责人决定集成，不能直接覆盖共享 DDR IP、时序约束或已验收候选。
3. 提交代码、参数、测试入口、当前结果和CURRENT.md。当前实验结果不再整体被忽略。
4. 构建目录与封存目录不直接进普通Git历史。新稳定位流、完整日志和数据用同一提交对应的Release附件发布，并同步更新附件清单。
5. 交接时注明成功、失败、尚未验收的范围，板上最后实际下载目标，以及下一位第一项任务。
