用户按提示把电脑端的 HDMI IN 源线拔下约 3 秒再插回。后续 10 秒 20 包均 RX/ALL done=true，观察器释放，用户报告 HDMI OUT 显示八色彩条。该窗口的数据为：

| 项目 | 记录 |
|---|---|
| flags / 故障 | `0x1dbf` / `0x15` |
| 报告几何 | 宽度 0，行数 1080 |
| PCLK 边沿 / 1 ms | 74,248–74,249，额定参考换算约 74.248–74.249 MHz |
| 好帧 | 始终 0 |
| 坏帧边界 | 9.5 秒增加 285 |
| I²C / CRC | 配置错误 0 / CRC 拒绝 0 |

`0x15` 表示 DE 在归一化 VS 有效期内出现。坏帧每个周期持续增加，而且好帧始终为 0，不能仅归因于一次历史粘滞错误。绝对坏帧起点包含启动时异常边界，不可当作正常视频累计帧数。独立 `struct/zlib` 对原始 50 包逐包重算、序号/tick 和解码字段比对均通过；输入评估器明确拒绝本次窗口。

## 已复现的数字缺陷与隔离候选

原 RX 初始化仅在轮询历史中看到 `209E[1:0]` 从 00 到 10 才继续设置。真实未改控制器的独立事务仿真表明：首读起持续 64 次返回 02 时，300 项初始设置已完成，但后续 7 项设置为零、RX done=0；同一 epoch 返回 00 再 02 后才完成。该结果证明模型内的启动活性缺陷，与实板拔插前后的行为相容；并非对芯片 PHY 锁定含义的额外推断。

原极性学习把首个 DE 高样本的 VS/HS 永久当成无效电平。完整 1080p30 数字反例只把第一个 DE 样本的 VS/HS 翻转一拍，随后全部正常：旧观察器持续 fault15、宽度0、好帧0、每帧坏计数加1，复现实板症状。真实芯片是否产生了该单拍瞬态仍待进一步实板对照确认；电脑 DTD 极性也不能直接等同芯片并行输出引脚极性。

新 `hdmi_uart_trained_diag` 仅使用独立新文件：RX 接受首次完整且全部成功的就绪轮询，并保留后续 00→02 重新设置；极性学习要求连续两段恰好 1920 拍、DE 期间 VS/HS 稳定且候选一致的有效行，再放行原严格光栅与好帧判据。锁定后的故障仍保持粘滞，不自动清除。旧观察器、共享 DDR/IP、旧位流及约束原件保持不变。

新候选已通过 RX 七场景，训练 11 场景，以及完整光栅同输入 A/B（新候选好帧3/坏帧0/1920×1080/qualified，旧候选 fault15/宽0）。原两极性、短行、停钟、粘滞、公共复位回归也通过。真实 checked I²C 驱动加新 RX/wrapper/原 TX 的七场景共 2117 笔有序总线事务全部匹配，2112 笔成功遥测逐笔正确，5 次 NACK 未计数。

训练证据是两段完整有效 DE，不单独证明 PHY 极性或中间空白长度；没有有效 DE 时可保持 unknown，主机应以无合格窗口判失败。最终资格仍要求固定 2200×1125 光栅、至少两好帧、像素率及新鲜度。
