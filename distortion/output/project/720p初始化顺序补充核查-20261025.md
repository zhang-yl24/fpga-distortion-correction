# 720p 初始化顺序补充核查

2026年10月25日，本项仅为来源与顺序审查，未修改初始化RTL、构建720p目标或访问摄像头。补充[有界时钟模型方案](ov5640-720p-bounded-clock-source-plan-20261025.md)：最终寄存器模型满足上界，不代表整条初始化流程或所有瞬间都满足同一上界。

本地OV5640 DataSheet v2.01的3036/3037默认值为69/03。按VCO模型，24MHz输入对应840MHz，27MHz对应945MHz；当前VGA附加表中的mult96也不能直接带入声称覆盖27MHz上界的新表。旧313项顺序仍含这些中间值和旧banding，不能只在末尾覆盖40/54后宣布整条路径通过。

DataSheet §2.5及§2.9、表7-1/7-2分别规定VCO上限、standby和时钟控制：软件standby不停止device clock；3103选择pad/PLL系统时钟，3039表示PLL bypass，均不能据此推断VCO已关闭。3102[0]虽标为PLL reset，但缺少可据以保证的保持/释放与锁定时序。复位默认阶段至首个受控写入之前，现有来源不足以证明VCO关闭。[本地原始PDF](<D:/English/FPGA/vendor/board/盘古100Pro+开发板（MES2L676-100HP）配套资料/4_IC_datasheet/OV5640/OV5640_DataSheet.pdf>)对应打印2-7、2-13及PDF104–106页。

[Linux v6.6的DVP配置函数](https://github.com/torvalds/linux/blob/v6.6/drivers/media/i2c/ov5640.c#L1525-L1564)与[Espressif v2.1.7的PLL函数](https://github.com/espressif/esp32-camera/blob/v2.1.7/sensors/ov5640.c#L192-L231)可提供寄存器顺序依据，但不能证明本地800MHz规格下的全部切换瞬态；其共同初始化也可能提前选择PLL。root/sysdiv位于VCO后级，不能把840MHz经root2分频后说成VCO仅420MHz。

下一离线实现可研究的动作序列是：明确保持pad系统时钟与standby，按位语义隔离PLL输出；先prediv6/root2，再mult84及其余分频，最后prediv3；逐项读回后再选择最终PLL路径。27MHz输入下，已写入静态配置的VCO模型依次为472.5、378、756MHz。这是寄存器定义与算术推导，尚非厂家为本载板验证的recipe；瞬态、锁定及低VCO可用性均不能从这些数字保证。

因此，离线应建立有序动作模型，包含reset、写入、读回、掩码与等待；逐条审计中间配置，保持旧报告原样。保证范围写成“显式配置并读回后的受控PLL模型路径”，保留此前未知区间，不承诺所有时刻VCO≤800MHz。它不阻止离线实现或候选PDS；受控实板另需明确输入来源、完整读回、无有效输入不授权，以及实际PCLK和2560字节×720行的新鲜度检查。串口一帧约20秒是导出预算，不能当成处理或传感器帧率。
