# 无显示器自动开发入口

本轮已通过串口实采CAM2原始图像，电脑直接读取原图。原始采集准入不依赖HDMI ready/HPD/EDID，无需为了抓图观看显示器；本轮没有独立确认HDMI线的物理连接状态。开发电脑通过COM5读取图像或状态，JTAG下载只写易失SRAM；每个受控短测结束后独立下载heartbeat并确认新的DONE。原始结果见[首轮实板记录](新镜头首轮实板记录-20261025.md)。

只要开发板供电、JTAG、串口和相机接线保持正常，可以自动完成下载、短批次采图、CRC/来源核对、状态读取及待机恢复，无需人工盯显示器。物理改接、照明/目标摆放和正式标定的多姿态采集仍需要现场动作。最终HDMI输出验收需要显示器或HDMI接收/采集设备；串口原图不等于HDMI成品输出已验收。

以下命令从`D:\English\FPGA`执行。所有新目录均位于用户已批准的`distortion/build/offline-20261024`。默认只验证和准备计划，明确加`--execute`才操作硬件；COM5是本机本轮端口，换电脑须重新识别。

## 原始图像短采

```powershell
python distortion/tools/bounded_native_bringup.py --binding distortion/output/project/ov5640-cam2-provisional-preprogram-20261025.binding.json --workdir distortion/build/offline-20261024 --port COM5 --frames 2 --seconds 35 --frequency 1MHz --execute
```

只采CAM2、640×480的传感器DVP输出；不运行本项目的畸变矫正、旋转或FPGA Gamma，传感器ISP自身处理另行记录。绑定前三项是文档、外观和用户接线声明支持的工程审阅，不是逐针/电压实测。程序实际下载成功后另存session-binding，不修改历史blocked模板。当前支持1–3帧、10–45秒接收，保存完整wire及原图，`result.json`同时报告采集结果与退出配置是否确认。

## 低负载温度读取

```powershell
python distortion/tools/bounded_diagnostic.py --target thermal_idle --thermal-build-dir distortion/build/offline-20261024/thermal-idle-build-20261025-173447-623 --workdir distortion/build/offline-20261024 --port COM5 --seconds 10 --frequency 1MHz --execute
```

thermal_idle只使用27MHz、LED和串口，无相机/DDR/HDMI输出。每条温度快照有序号及CRC16；接收后恢复heartbeat。下载工具通过只表示收到字节和退出配置成功，实际ADC有效、故障、样本年龄、报警和数值由独立分析器核对：

```powershell
python distortion/tools/analyze_headless_diagnostic.py --target thermal_idle --wire 本轮目录/received-status-wire.bin --output 本轮目录/decoded-thermal.json
```

温度按现有内部ADC近似换算，未经外部校准；60℃是项目保守门槛，不是器件额定温度。本轮低负载读数不能代表另一次raw/DDR配置的温度。

## 曝光、增益和白平衡状态

```powershell
python distortion/tools/bounded_diagnostic.py --target camera_isp_probe_d5 --probe-build-dir distortion/build/offline-20261024/camera-isp-probe-d5-20261025-retry1 --workdir distortion/build/offline-20261024 --port COM5 --seconds 15 --frequency 1MHz --execute
python distortion/tools/analyze_headless_diagnostic.py --target camera_isp_probe_d5 --wire 本轮目录/received-status-wire.bin --output 本轮目录/decoded-isp.json
```

该探针先按参考表初始化写传感器和HDMI，再读取24个ISP寄存器；不是完全无写。D5修正版通过独立整板时序与55个实际引脚核对，旧AA22探针被新入口明确拒绝。多字节曝光/增益不是原子快照，探针重新初始化后的值也不是前一次raw曝光时的同步读数。初始化失败时扫描器可能静默；这种情况只能报告无数据，不能猜失败寄存器或传感器身份。

诊断SRAM下载使用1MHz，入口拒绝100KHz；100KHz仍可用于只读扫描，避免3.8MB位流在固定短超时下中断。

## 当前优先使用guarded短采

已完成guarded板级集成、最终PDS和七项CAM2受限实板测试。优先使用`guarded_native_session.py`，具体命令、实际图像、另一眼失败和颜色门槛见[持续开发成果](持续开发成果-20261025.md)。上方旧短采入口保留作首轮证据复现，不含后续guarded联锁。

新入口支持默认未授权、明确有限GRANT、重复包去重、STOP排空、温度/快照失效阻止新增事务。主机停止TX的实测保持COM接收，没有拔USB或杀进程。核心时钟停顿会暂停核心域租约计时，主机`finally`也不能保证进程被杀或JTAG断开后恢复；长期无人值守仍须独立验收。
