# 恢复预算修复与离板回归（FPGA-1027-RECOVERY-OFFLINE）

本轮仅离板修改host及模拟测试。开发板维持用户确认的断电状态，前次硬件授权已耗用。**没有COM/JTAG扫描、板卡访问、下载/Flash、重试、PDS或整体RTL仿真；没有新真实硬件计划或硬件授权。** 测试产生的plan均为合成fixture：伪位流、被替换的验证/设备API或不存在的PDS路径，不能作为真实硬件执行计划。

原SRAM-ONE整轮仍passed=false/CLI exit1；候选和有限0°UART通过，恢复超时并无新DONE。原计划、result、两个receipt、日志等20份保护文件全部SHA不变，没有补写成功、迁移或复用旧计划。

## 事故依据与预算计算

固定heartbeat及候选sbit均3791112B，1MHz。原候选program.out.log明确Program30.9秒；该日志创建到最后写入窗口42.793秒，支持“完整shell约43秒”的近似判断，没有精确Popen耗时字段。恢复shell只有30秒wait，超时后自有进程被清理，无本次编程后新scan/DONE。原外层PowerShell直接跑CLI、工具yield/轮询只等待，没有外层hard timeout先杀finally；CLI和finally正常结束并写出了失败记录。

新最低客户端预算采用可复核工程策略：

`ceil(1.5 × (完整文件字节数 × 8 / JTAG频率 + 20秒))`

当前1MHz：完整文件按位估算30.328896秒，加20秒shell连接/设频/前后scan等余量后乘1.5，向上取整为**76秒**。这是假定全文件传输的工程估算，未解析sbit封装，不声称是芯片规格或严格物理下界。观测shell约43秒与Program30.9秒用于检验该余量的合理性。

默认候选和恢复客户端均**90秒**，最大**120秒**。显式传入80/100等合格值会保留；小于计算最低值、超过120、缺失、bool/NaN/Inf或与封存计划不一致均拒绝。1MHz当前文件的30/60/75秒均在准备/预检阶段拒绝，不用自动延长覆盖用户值。未支持的频率或尺寸组合若无法在120秒内满足策略，直接拒绝。

## 四层时间合同

| 层级 | 默认值/边界 | 精确含义 |
| --- | --- | --- |
| UART观察 | 最多30秒，原12–30规则不变 | 仅UART状态/命令/保持/最后auto-off观察，完成可提前结束 |
| 候选完整program shell | 90秒/客户端，最大120 | scan客户端也各有同一独立预算；不只是裸Program命令 |
| 恢复完整program shell | 独立90秒/客户端，最大120 | 同样分别用于scan和program；不是整段恢复只准90秒 |
| 清理/外层等待 | 单阶段已知等待项240秒；默认外层等待600秒 | 必须覆盖候选、UART及完整finally，不能用剩余UART时间截断恢复 |

单阶段已知等待项=两次server启动各10秒 + 两个client各90秒 + 最多4个owned进程各terminate wait5/kill wait5秒，即20+180+40=240秒。候选240+UART30+恢复240+校验/close/写日志余量30=**540秒最低外层等待合同**；默认600秒，最大900秒。若显式客户端预算变大则下界重算，默认外层取max(600,新下界)；显式外层小于下界或大于900均在候选动作前拒绝。没有把每client预算误写成整段上限。

outer_wait_seconds是封存给调用者/监督者的等待合同，**本CLI没有新增外层自动kill计时器**。已核原实际运行器没有hard timeout；后续外部runner若配置hard timeout，须审核其等待满足合同且不提前杀finally，代码不能控制任意外部kill。文件IO、调度及异常close不是实时系统硬上界，因此240/540是已知阻塞项的保守核算，不是整个进程必在该秒数内结束的保证。

没有新增主机失联看门狗。主机死机/被杀、掉电或JTAG失联时，finally仍无保证；关COM/auto-off仍不停止视频。

## 最小源码变更

仅两个runtime helper：

- `tools/program_idle_heartbeat.py`：新增纯文件预算计算/校验；准备接口要求调用方显式绑定timeout；计划包含program_budget及位流尺寸/频率/策略/上下界。执行默认None时读封存值；显式传入值不等则启动任何进程前拒绝；磁盘plan也须一致。保留原固定heartbeat/源/引脚/脚本及新DONE门禁、owned清理。
- `tools/gamma_pipeline_session.py`：候选及恢复分别封存program_budget；time_budget记录UART、两段操作核算、外层合同。verify在候选前核验缺失/失配/过小预算；finally只独立核恢复计划并传其封存值，不再硬编码30。候选编程也读取自己的封存预算。`--execute-plan`携带任何预算覆盖参数在读取计划前明确拒绝。

公共idle.prepare_plan的低层API不再替旧调用者猜预算；新版Gamma和heartbeat CLI明确传90秒。旧gamma_capture_k320_dev_session/guarded_pose_batch/raw720等仍有硬30/60，其他旧入口也未显式声明预算，本轮不改这些分支。它们的新计划准备会提前失败，不能当作可执行入口；旧计划也因helper哈希/新字段/已用状态拒绝，不会在上板后才默认覆盖旧值。后续如要恢复某旧入口，须单独补预算合同、生命周期检查及新审核，不能复用原授权。

没有修改program_native_raw共享进程执行/清理实现；定向真实假子进程测试直接验证了它已有的wait timeout和owned清理。没有重构采集框架。

覆盖：

1. 虚拟时间scan5秒+program43秒，经真实idle._client和新DONE解析链，在封存90或显式80秒预算内成功；验证wait实收相同值，无长sleep。
2. Python受控假子进程实际wait0.2秒超时，只清理列入owned的子进程；另一个同为测试创建但未列入owned的sentinel仍存活，最后由测试自行回收。没有调用真实PDS。另用fake对象验证terminate wait5超时才kill/wait5，未列入对象零动作。

6. 两个client、server启动和owned清理均计入外层等待核算；显式550秒可保留，539秒低于540被拒。
