以下命令从仓库根目录`D:\English\FPGA`执行。无需接板；不打开串口，不调用PDS/JTAG，不改旧参数和稳定位流。Python依赖沿用`requirements-team.txt`，本轮实测Python3.13.3、NumPy2.2.5、OpenCV4.11.0.86。不要仅因未知型号先安装新驱动或生成相机初始化表。

## 一次运行离线验证

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
python distortion/tools/run_new_camera_offline.py --workdir distortion/build/offline-20261024 --output distortion/output/project/下一次离线检查.json
```

`workdir`必须是用户已经批准并存在的build子目录。输出必须是现有`output/project`中的新文件名，拒绝覆盖既有报告。测试工具会在该scratch目录内创建临时文件；不要直接在旧证据目录运行会写文件的实验命令。新采集目录在接板时再确认，本次不预建。

入口依次核对4个历史稳定位流及其源码/依赖，运行与CI同一组20个CPU测试文件，确认未知相机/未经review的新下载被拒绝，计算双眼VGA30探索预算，检查合成VGA的12个30°步进角度加13.7°（3,993,600个坐标），并验证超出定点域的合成负例确实被拒绝。可用`--rtl-report`读取已保存的raw仿真JSON，核对源码/日志/字节流SHA并通过新主机接收器回放；不会自动调用Vivado或PDS。报告保留实际命令、退出码、环境版本、日志/报告SHA和所有生产Python源码SHA；测试前后源码不一致即判失败。

该入口不运行耗时PDS或旧硬件实验脚本。通过是本地CPU验证；修改后的GitHub workflow尚需提交/推送后才会产生新的云端运行。

## 1. 相机身份与模式预算

硬件档案模板是`new-camera-profile.template.json`，未知事实均保留null。复制为新文件并根据实物/资料填写，不能把模板当已验证配置。

```powershell
python distortion/tools/camera_mode_preflight.py --profile distortion/output/project/new-camera-profile.template.json --scope raw-capture
python distortion/tools/camera_mode_preflight.py --explore --width 640 --height 480 --fps 30 --cameras 2 --new-output-fps 30 --display-fps 60
```

第一条在空模板上**应返回退出码2并列出阻塞项**。`raw-capture`用于先取得真实标定图，不要求先完成新镜头标定；`corrected`用于矫正候选，额外要求新标定。身份、接口、电气/引脚、输入模式和该作用域的候选配置核验始终需要。单路可明确填`synchronization=not-applicable-single-camera`；双路不能使用这项豁免。资料核验字段是用户/工程记录声明，工具不独立检查硬件，两种作用域均不授权下载。

第二条是显式假设预算：每眼有效DVP字节时钟18.432MHz，双眼输入合计36.864MB/s，共享125MHz核约6.7817周期/输出像素。相机输入、新矫正帧、显示刷新分别计算。消隐、DDR刷新/突发浪费/等待均需实测，不由预算推断支持双眼30fps。

银行地址单位是4字节，工具检查容量、对齐、不重叠及28bit地址合同；物理DDR容量须另填。每眼4银行只是存储提案，当前双路仲裁/采集RTL未实现。旧48MHz DVP约束与D5=AA23只描述旧接线和模式，不能直接移植到未知接口。

## 2. 新镜头内参档案

当前优先使用新`fisheye-dataset-manifest.template.json`和`calibrate_fisheye_profile.py`从身份绑定的真实原始数据直接生成档案，避免人工复制。`fisheye-intrinsics.template.json`仍可用于检查格式；目前没有真实新K/D。历史`tools/calibrate.py`输出的是比较结果，若使用旧入口，须从`candidates.fisheye`提取`model/image_size/K/D`并另行补齐真实来源绑定；不能把整个比较JSON直接传给映射/双目工具，也不能选择旧导出器特有的`fisheye2`冒充新四系数模型。

填写当前`camera_id/lens_id/profile_id/capture_mode_id`、真实来源标记、原标定文件路径与SHA。`D`必须有完整4项；K为零skew的常规3×3矩阵。`calibration_image_sha256`列出所有参与内参拟合或模型选择的图像SHA，供双目留出独立性检查；不要只列部分训练图。

内参中的`provenance=real_chessboard_captures`仅用于真实镜头采集。它是可追溯资料的声明，不由一个字符串自动证明真实性。换镜头、输入尺寸、传感器裁剪/翻转或机械结构后按任务重新核查标定。

## 3. 四系数鱼眼到现有定点核心的审计

在新内参档案真实存在后运行，例如：

```powershell
python distortion/tools/wideangle_mapping_audit.py distortion/output/project/new-left-intrinsics.json --angles 0 30 60 90 120 150 180 210 240 270 300 330 13.7 --output distortion/output/project/new-left-mapping-audit.json
```

可用`--output-size W H`、`--output-k 新输出K矩阵.json`单独指定输出投影；输出K文件本身是3×3数组。默认拟合现有三项Brown径向近似，保留完整fisheye四系数作为OpenCV参考；不修改稳定includes或产生可直接下载位流。

检查每个请求角度的全帧坐标：max/RMS/p95误差、参考与定点的四邻域都在源图内的比例、局部Jacobian折返、旋转/算术失效，并对边界及内部坐标逐角度核对独立整数oracle。默认最大近似误差0.25px，失效/折返为0；默认覆盖下限0.5仅是数值诊断门槛，**不能当最终画质或保留视场验收**。实际输出视场与覆盖要求须先按项目任务登记，可用`--minimum-in-bounds-fraction`指定。

`--stride`大于1只做抽样诊断，即使样本误差很小也不能通过全帧候选。默认每帧最多2,500,000点，分配数组前检查；更大问题须显式指定`--maximum-points-per-frame`并评估内存。当前结果只对请求的K/尺寸/角度有效。

数值`passed`不等于光学合格。真实身份及来源齐全仅可标记进入profile复核；`hardware_release_allowed`始终false。还需新的radius guard、参数化候选目标、RTL回归、最终时序、源码/位流绑定及实物画质验收，不能复用旧guard直接下载。

## 4. 显式配对的双目离线标定

模板为`stereo-capture-manifest.template.json`，真实棋盘尺寸和同步偏差门槛默认未知。每对填写pair_id、train/held_out，以及左右路径、源帧ID、图像SHA、曝光时间戳和共同clock_id。路径相对manifest文件，绝不按文件名排序猜配对。左右独立内参身份必须与manifest匹配。

```powershell
python distortion/tools/stereo_fisheye_calibrate.py distortion/output/project/new-stereo-captures.json --left-intrinsics distortion/output/project/new-left-intrinsics.json --right-intrinsics distortion/output/project/new-right-intrinsics.json --output distortion/output/project/new-stereo-calibration.json
```

默认至少8训练对、3独立留出对；实际应采更多不同姿态，依据覆盖和稳定性补采。训练对固定左右内参求R/T，留出对只评极线y残差。平移/基线单位mm，变换为`X_right=R@X_left+T`。默认训练RMS≤0.5px、留出y的p95≤0.5px、最大≤1px均是内部工程门槛，不能作为赛事或物理测距精度标准。

工具检查缺眼、尺寸、身份、重复pair/frame/图像/角点、内参与留出图的SHA泄漏；图像检测前再次核对SHA，不静默丢弃失败棋盘。同步合格须有支持的硬件同步方法、曝光共同时间基准、偏差满足预先登记门槛，以及SHA绑定的物理同步证据和人工审阅声明。相同软件时间戳/帧率、相邻文件名或USB到达时间都不能证明曝光同步。软件只检查证据合同，不解读示波器波形或替人判断真实性。

数值通过与`stereo_acceptance_ready`分别报告；合成、缺同步或留出来源未核实均不能进入接受状态。即使离线资料齐全，`hardware_release_allowed`仍为false：没有由此生成的双路FPGA顶层、实时同步、深度精度或整板验证。
