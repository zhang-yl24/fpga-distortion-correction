# Guarded raw 板级候选最小集成方案

本文件是待实现/验收方案。现有 `raw_camera_capture_cam2_ref` 的97项源码、已生成位流和下载helper保持不变。已经通过的 `raw_capture_lease` 与 `raw_camera_capture_guarded` 只有独立数字仿真证据；尚未与UART命令、温度及真实板卡集成，不能据此宣称无人值守安全。

## 独立目标和最小依赖

后续新增单独 `raw_camera_capture_cam2_guarded` 目标和专用顶层/FDC/pins/build/source清单。复用旧CAM2物理接口、DDR/PLL、raw核心与921600发送器，新增RX=B24（来自已验证主控目标）。`uart_rx_control` 必须显式设置921600，不能沿用默认115200。新目标不得导入Brown、Gamma、旧标定或旋转数据通路。

温度复用 `logos2_temperature_monitor` 和 `adc_temperature_reader`，运行在27MHz；ADC DCLK允许范围1..100MHz，不能直接接125MHz核心时钟。先用独立低负载诊断目标确认真实温度valid/raw/age/failed/over_temp/alarm，再集成授权门禁。

## V2命令与确认边界

复用A5 5A包头、16位序号和CRC16/CCITT-FALSE算法框架，但使用独立版本02和独立操作码，明确拒绝旧版本01的角度/auto命令。建议操作码为10 grant、11 stop、12 query；CRC覆盖版本、操作码、序号及全部参数，不覆盖包头和CRC字段。grant参数可在32位内编码帧数1..3和租约毫秒1..24000，转换至125MHz周期前先检查范围和乘法溢出。

重复序号的完全相同命令只报告duplicate，不再执行；同序号不同参数拒绝。采用明确的序号前进规则，旧命令回放不续租。query只读状态，不续租；stop只禁止新增事务。grant仅在上一批完全排空、相机/DDR/温度就绪且前一次grant电平已撤回后接受。板上无有效grant时默认不采集。

ACK必须区分命令已解析、授权已接受、帧已完成和批次已排空，不能把UART写入成功当硬件执行成功。状态应包含boot/session标识、接收/接受序号、accepted/rejected/duplicate计数、租约/帧预算、阶段、frame_id、完整帧计数、CRC及停止/故障原因。主机只能依据新鲜匹配序号和阶段推进判断进展。

## Raw输出与状态帧

保留PGFRAME1原始帧，不把ASCII状态插入像素payload。新增有独立magic、版本、长度、CRC的状态帧，在完整PGFRAME边界输出；UART只能有一个串行驱动和明确的包级仲裁。状态快照在同一时钟边沿锁存，发送期间不变。

VGA RGB565帧约614444字节，921600/8N1下单帧串行发送约6.7秒；发送期间主机可统计收到字节进度，状态轮询超时必须区分完整帧传输和真正失联。若已发出的raw帧半途故障，不能无定义地插入状态破坏解析；第一版可以由主机超时保留失败原始流，再按受控路径下载heartbeat。需要帧内状态时应另外设计分块传输，不能假装现有PGFRAME支持它。

## Reset、lease和fault

有限租约是新增事务期限，不是立即断电。到期、stop、温度联锁只门控下一次request，已接收的DVP/DDR/UART事务继续排空，不能在已接受的DDR突发中途复位。源银行保持冻结到最后UART停止位确认；故障后锁存requires_reset，不能假装源银行已释放。

共享复位必须同时作用于FIFO的两个时钟域并在本地同步释放。主机失联不能使卡高grant自动续租。需要恢复时先保存故障和原始日志；完成受控全板复位/重新下载后使用新会话授权，不自动无限重试。

租约结束后DDR时钟和电源不一定停止，不能称为heartbeat或物理低温已经确认。无人值守前仍需实测失联、传输故障、温度上升、退出和重新进入空闲的全过程。

## 温度域与无帧诊断

27MHz域先根据sample_valid、failed、sample_age、raw/code12及报警形成失效关闭的联锁决定，再同步单比特至核心。多位温度快照跨域使用held-bus握手，不逐位采样。温度无效/陈旧时不得接受新grant。现有约85℃硬件报警不是项目60℃保守测试门槛；阈值与换算需独立核对，不能由JTAG mode3某一位推断真实温度正常。

无帧时，状态必须分别指出：sensor_id与SCCB ACK、初始化失败寄存器/期望值/读回值、DDR init/PLL、预热是否完成、是否已授权、租约剩余、采集/导出状态、source_valid/CRC错误、温度是否就绪。仅串口没有PGFRAME不能确定是哪一阶段失败。暗图/偏绿还需独立读取曝光、增益、AWB、输出格式、测试图案及pad/同步配置，不能靠重新拟合镜头参数掩盖。

## 验证关卡

1. 专用V2协议、CRC、超时、错误版本/操作码、去重与旧包回放负例。
2. RX到授权控制到真实raw核心到包级TX仲裁的数字联合仿真，包含预算、租约、背压、半帧故障、ADC无效/陈旧和温度联锁。
3. 独立整板PDS最终时序、全部active pins、源码/IP闭包和位流SHA绑定。
4. 有人在场的短时实板grant/无帧诊断/失联/温度/退出验证，结束实际确认heartbeat DONE。
5. 验证完成后再允许主机按有限总批次重复采集、校验、冷却及重新授权；查询不续租，不把模拟或状态配置当实板验收。
