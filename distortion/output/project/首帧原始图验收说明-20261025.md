## 不用棋盘格即可验证

| 项目 | 首轮可确认的证据 | 不能由此推出 |
| --- | --- | --- |
| 连接与配置 | 有效FPGA器件/ID读回；另有明确的SRAM下载成功和DONE回执；传感器ID/初始化状态单独保存 | USB下载线出现不等于FPGA已识别；串口出现不等于相机正常 |
| 原始完整帧 | 本轮summary、metadata、原始RGB565和PNG齐全；尺寸/字节数、源/接收CRC、SHA和逐像素位复制一致 | 接收完成不等于光学画质、标定或实时矫正通过 |
| 来源与身份 | 本轮camera/lens/profile/mode/CAM接口声明和原binding一致；源码/位流/引脚/最终时序及原始帧角色重新读回核对 | PGFRAME1不携带眼号；身份声明不能冒充线上身份认证或实际接线的独立测量 |
| 自然场景初查 | 观察原图；统计全黑/全白、RGB代码、饱和、D5两个传输字节位平面、行列重复和周期性；保存原尺寸掩码 | 镜头盖、黑边、静态或周期纹理也会产生异常统计，不能直接归因于坏线/坏传感器 |
| 多帧变化 | 同一声明接口/模式下比较完整像素和差异；需要判断更新时，记录现场目标变化及相应短组原始图 | 静止场景同图不证明卡帧；事务ID和主机接收时间不证明独立曝光、相机fps或双目同步 |

每项只记录本轮实际证据。先解决原始帧完整性、来源和明显颜色/数据位问题，再进入几何矫正。自然场景可以帮助定位初步故障，不能替代标准光学验收。

## 首帧的独立只读复核命令

取得真实summary及其原始binding后，使用下面的入口。将占位路径替换为实际文件；输出必须另取新文件名，父目录必须已经存在，禁止覆盖原始数据和历史报告。

```powershell
python distortion/tools/native_scene_diagnostics.py --summary 实际采集汇总.json --binding 原始会话绑定.json --output distortion/output/project/实际场景诊断-唯一编号.json --masks-output distortion/output/project/实际场景掩码-唯一编号.npz
```

报告须分别读取`file_integrity_passed`、`native_source_contracts_verified`及`source_kind`，不能把某个总通过标记当作所有来源条件均成立。工具不打开COM/JTAG，不修改板卡；没有原binding时会明确保留构建/角色验证缺口。`.npz`保留原尺寸有效分析、黑、白和饱和等掩码；原始像素不被裁切或覆盖。

## 棋盘格到货后追加

1. 实测内角点数、方格尺寸和板面平整度，固定本轮摄像头/镜头/分辨率/裁切/方向及相关ISP设置。
2. 按`fisheye-dataset-manifest.template.json`明确训练、选模与留出姿态，覆盖中心与边缘，检查重复姿态和SHA；不能把连续相邻帧当成独立姿态。
3. 用`calibrate_fisheye_profile.py`只拟合训练图，检验独立留出误差、覆盖、有限性与单调性；生成绑定本轮身份的四系数档案。
4. 新档案声明的可用射线范围继续约束映射与双目标定。商家标称200°不等于已实测支持全200°；当前前向透视/OpenCV路径不能承担超过180°的全场景认证。
5. 对应原图/矫正图的直线度、有效视场、边缘拉伸和独立光学重复实验另做。专业清晰度需适合的斜边图卡；标准色差需颜色目标及照明条件；棋盘本身也不能证明双目同步、深度精度、系统帧率或端到端延迟。

本轮先获得可信的自然场景原始帧，正式几何参数和光学成绩等待相应实物与独立证据，不填入估计值。
