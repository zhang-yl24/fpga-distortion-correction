# AA 资源优化：两个独立离板候选

**研究状态，不可直接烧板。** 当前目标保持 HDMI 摄像头 1920×1080、标称 60 Hz、KEY1 RAW/CORR、固定 Brown、零旋转、Gamma OFF。这里没有新位流、厂商实现或实板结果，也不替换当前AA冻结源码。

- **AF54：优先做同配置Map。** 在显式输出tile顺序契约下，用已有query ordinal恢复可推导的tag位；cache接口仍 25 位，实际 4096 深度 query FIFO 由 63 位变 54 位，声明负载少 36,864 bit。28,560个查询及真实DDR/fill模型逐周期差分通过，FIFO满、最后 24 行条带/最大tag及忙态坏tag拒绝均有证据。物理DRM/LUT/FF和时序收益未测量。见 [AF54](af54/README.md)。
- **AE：单表达式前景重复检测。** native配置用 7 位 line 相等代替 14 位 block 相等，使四个head_block寄存器及专属运算不再有native功能消费者；27,100查询的真实HEAD0/TAG25/FIFO63差分通过。56位寄存器是结构机会，不是已经测得减少 56 FF。见 [AE](ae/README.md)。

两者都从 AA 独立派生，**没有相互叠加**。也没有加入AD路由优先级或late-select等待。先保持完全相同的PDS/IP、TOP、参数、器件、时钟、约束和种子，分别比较baseline/AF54、baseline/AE；Map值得后再继续布局布线、独立STA和同版相机验证。原 AA 3 ps setup余量不能借给新实现。

本轮刻意补的是此前缺失的实际 RTL 门禁，而不是重跑旧 Gamma 六帧或把旧 HEAD1研究改名。实际 AA 是 HEAD0、TAG25、原 FIFO63；早期AC的124→95位数字不适用于它。所有模型、source hash、脚本与覆盖边界分别保存，未运行项明确为未运行。

当前单像素每核心周期的吞吐上限是 125,000,000/2,073,600≈60.28 帧/秒，尚未计入任何停顿或边界开销。60 帧预算只剩约 9,733 周期的开销空间。这两个资源候选不减少等价 RTL 周期，不能据此承诺更高输入频率、新呈现FPS或端到端延迟改善。

真实电脑离线且云端缺匹配授权 PDS/IP时，Map/STA无法运行；本目录把下次可执行的步骤准备好，不把 Icarus或参数绑定检查当作物理实现通过。当前可烧板 AA 及 600 秒主机采集工具仍见 [AA交付入口](../../delivery/20261107-camera1080p60-key1-aa/README.md)。
