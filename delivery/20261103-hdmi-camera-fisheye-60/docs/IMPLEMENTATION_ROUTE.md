# 与用户指定技术路线的对应

本候选以已上板的 `20261103-hdmi-camera-fisheye-c` 为基线。保持当前标定、RGB565 存储与双线性插值，目标为 1920×1080 每秒 60 个新校正帧。原 C 版源文件和封存证据保留。

| 技术路线 | 本候选实现 | 验证要求 |
| --- | --- | --- |
| 8 拍填充与邻点地址预计算 | 64 bit 奇偶 RAM 直接接收 8 拍 DDR 返回，四邻域地址及边界在 FIFO 入队前寄存 | 像素、分数、边界、标签、冷/热缓存、替换、复位、协议异常 |
| 8×8 分块与双 stripe 写回 | 两路分别处理同帧上/下部分；8×8 访问，双条带恢复光栅次序；两组 burst 缓冲并发接收与写 DDR | 条带跨界、背压、CRC 合并、两个半帧全覆盖且无重复 |
| DDR 完整返回束寄存 | 数据、valid、last、ID 同拍寄存；寄存前检查原始事务归属 | 无主返回、同拍 AR/首拍、重叠请求、错误末拍、复位 |
| 按真实关键路径补流水 | 描述符/launch 寄存、缓存 metadata 同步读取、两项 RGB/tag FIFO、条带本地地址、输出取像素寄存与末帧计数/CRC 延后确认 | 每次 RTL 修改后核对功能，重新综合、布局布线与 STA |
| 三源帧缓存与描述符队列 | 源槽 0、1、4，结果槽 2、3；完整帧所有权及源释放与实际引擎完成绑定 | 独立相位模型、真实 DMA/系统循环、排队延迟、复位清理 |
| DDR 约束审计与分层验收 | 逐字核对厂商 IP、原有 RCF、三条厂商时钟关系；分别报告像素/CRC、系统争用、物理时序和板测 | 最终编译输入、约束执行、时序数据库与位流身份一致 |

处理顺序遵循用户路线：先完成 fill8 和分块/重排功能，再修关键路径，再接入并检查帧槽调度，最后进行实板长期测试。控制与输出模块可以并行开发，验收结论仍逐层区分。

8×8 保留为默认基准。32×8 为可复现实验配置，实际访问模型和 RTL 均显示它与 8×8 的填充次数相同，因此宽度变化未被视为性能收益。缓存容量以参数实验评估，保持 8 拍填充和相同图像结果。

选定配置采用上路 256 KiB 行对齐缓存、下路 128 KiB 线性缓存，以及 640/440 行分工。分工调整使两路在高延迟模型下接近同时结束；每帧仍处理全部 1920×1080 像素，完整标定坐标保持一致。交付 I 阶段在 12/40 周期首拍延迟压力模型中分别测得约 73.83/60.19 FPS。具体周期、像素核对和交付源码绑定见 README、VALIDATION_STATUS.json 与 evidence。该模型用于检验处理预算，实板新显示帧率单独验收。

物理检查发现 PDS 对旧 `async_reg` 属性不生效，已改用 `PAP_ASYNC_REG=1` 和 `syn_srlstyle="registers"`。G 阶段最终路由网表中的 34 条 FIFO Gray 同步链均保留独立两级触发器，逐边核对 source Q、第一拍 D/Q、第二拍 D；共享复位链也核对实际连接。跨时钟路径的延迟、总线偏斜与复位释放另行验收。

HDMI 扫描 60 Hz 与实际新校正帧率分别统计；重复显示计数、FIFO 欠流、CRC/协议错误和冷启动/复位测试单独保留。
