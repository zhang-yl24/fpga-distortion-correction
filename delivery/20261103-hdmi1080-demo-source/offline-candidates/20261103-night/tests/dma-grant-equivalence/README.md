# DMA grant-fire paired unit review

Run `python -B run_pair.py` after extracting this self-contained package. Python 3.9+ is required. The runner prefers Icarus Verilog (`iverilog`/`vvp`) on PATH; on Windows it can otherwise use the official installed Vivado XSim 2017.4 tools. Select `--backend icarus` or `--backend xsim`; `--tool-bin` overrides the installed XSim bin path. No installation is performed. Missing tools produce a `NOT_RUN_MISSING_*` result, never an HDL pass. `python -B run_pair.py --check-only` checks source hashes and the original CPU oracle mutation tests only. On this host XSim must use the formally approved outside-sandbox command entrance, avoiding the known sandbox compiler-DLL failure.

The original descriptor2 TB, both vector files and oracle are byte-exact copies. Each DMA is independently compiled and simulated with the same native capture/FIFO dependencies and unchanged six-frame/1,536-pixel stimulus. The original four CSV checks, stalled descriptor/prefetch assertions, full-queue reset, reserved-capture reset and simultaneous pop/push witnesses remain intact. The only DUT difference is DMA line119 `if(grant_valid && grant_ready)` to `if(grant_valid)`.

The added second top `unit/dma_public_trace.sv` observes every DMA public input/output at every sys_clk edge, both before NBA and 1ps after it. The trace includes clock values and picosecond timestamps. It changes no signal. Pre-edge assertions check both complete two-bit reset releases, `active==capture.grant_busy`, and `grant_valid` implies `grant_ready`. Each original oracle must pass independently, then both complete traces and all four original CSVs must be byte-identical.

Every compile, XSim elaboration and simulation has a 30-second wall timeout. XSim uses the official `xvlog --sv`, `xelab <both tops> -mt off` and `xsim -runall` commands, with per-stage PowerShell scripts/logs. On timeout/interruption only the spawned process tree is terminated, with bounded waits; files are retained for review and no recursive deletion occurs. Results go to a fresh directory under `results/`; `--out results/<fresh-name>` selects one. An existing output directory is refused. HDL PASS requires both simulations, both original oracles, positive invariant witnesses and the full byte comparisons. Source hashes are checked again after the run.

`SOURCE_BINDING.json` records exact native/history origins and whether old unit dependencies match the new native. `MANIFEST.json` binds immutable package contents; generated `results/` are excluded. `LOCAL_PREFLIGHT.json` records packaging-host availability. This package does not run native Map/PNR/STA, alter production, access hardware/serial, upload, or authorize hardware release.

The local approved XSim run passed both independent compilations, elaborations and simulations. Preserved evidence under `evidence/xsim_approved_pair_a/` contains the actual command scripts, logs, four original CSVs, both full public traces and result JSON. Each trace has 12,046 rows over 6,023 sys edges, 2,615,392 bytes and SHA256 `bcbfb50e2d114b3cd8ef195ff10b45478fa0429ab76f44df007193fc1d460d88`; both full traces and all four CSVs compare byte-identically. Each side checks 5,986 nonreset pre-edges, 7 grants and 37 reset edges. The executed manifest preserves the pre-evidence package binding; final packaging adds evidence and updates packaging documentation, without changing the executed runner, observer, DUT, original TB, oracle or vectors. The result's `commercial_EDA_or_hardware_used=false` means no synthesis/Map/PNR/STA or hardware flow; its explicit backend records the authorized official XSim functional simulation.
