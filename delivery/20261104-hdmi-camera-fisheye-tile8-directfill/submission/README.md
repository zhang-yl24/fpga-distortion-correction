# 1080p15 选定提交版

本目录只包含tile8 direct-fill INDEX8 v3一个1080p执行位流。输入1920×1080约60 Hz，输出扫描30 Hz，实测约15个新校正帧/秒；保持当前KB4镜头参数及既有输出视场。

唯一位流：`bitstream/hdmi_camera_fisheye_top.sbit`，SHA256 `aa21991374fbeb4a6733741095f38e27336f1e47dd67b963feb243428a5b353b`，设备`Logos2-PG2L100H--6-FBG676`。这里只提供位流，不会自动执行下载。

## 文件组织

- `source/`：110个实际生产输入的原样副本，保留相对distortion目录结构；另含同次RCF布线约束。
- `compiled-snapshots/`：实际编译时改变的6份源码快照，逐字保留原内容。5份为绑定头文件路径迁移，1份为顶层INPUT_TIMING_CONFIGURED由0变1；其余104份编译字节与原源一致。
- `build-plan.json`与`production-source-manifest.json`：原始构建输入与变换记录，不重写历史绝对路径。
- `evidence/`：该位流真实SRAM下载、30秒与600秒采集回执、原始UART字节、保存的独立复核、最终物理证明及来源身份。
- `../reports/`：完整最终STA报告的gzip、原样十表摘要、最终Route Optimize资源日志与引脚报告。均由本清单与验证器校验。
- `source-manifest.json`：所有选定文件的大小、SHA256、来源与角色；来源中的历史路径仅作追溯，离线验证不访问那些位置。

## 解压后核验

在安装Python 3.9或更新版本的环境中执行：

```text
python verify_selected.py
```

只需Python标准库。验证器核对全部选定文件、110源与6编译快照、唯一位流、保存的下载/板测/资源/时序身份，以及gzip解压后的完整报告SHA；不依赖Git、旧A/B/C/D归档、PDS、串口或JTAG。返回`passed: true`表示选定包完整且所存证据身份一致，不代表在当前电脑重新完成了EDA或上板验收。

## 源码与重建边界

这里完整保留选定生产输入、6份实际编译差异和原plan，不宣称一条便携命令即可重建完全相同的物理实现。原plan是首轮原生构建输入；后续物理约束应用、STA和位流生成的身份链保存在最终proof、summary与bit-verification中。历史`P:/`及工具安装路径是原记录，不能在另一台机器上不加核对地直接执行。

`assemble_selected.py`是本次材料组装来源记录，运行它需要原始本地冻结归档；提交包使用者只需运行`verify_selected.py`。完整物理proof采用无损gzip，解压SHA与保存的板测/位流身份一致。
